# Autonomous Earthworks Simulator — Bulldozer

The Desktop excavator project's source layout and four-wheel movement base,
renamed for a bulldozer. The excavator arm, arm controls, and excavator mesh
are removed. Bulldozer tracks, blade, and their dependencies come later.

## Files

The ROS package is inside `bulldozer/`, just as his is inside `excavator/`.

| File inside `bulldozer/` | What it does |
| --- | --- |
| `launch/robot.launch.py` | Starts Gazebo, spawns the vehicle, and connects ROS. |
| `urdf/bulldozer.urdf.xacro` | Defines the chassis, four wheels, and movement. |
| `config/bulldozer_bridge.yaml` | Connects ROS commands and Gazebo feedback. |
| `worlds/bulldozer_empty.sdf` | Defines the ground, light, and Gazebo controls. |
| `package.xml` | Names the package and lists its dependencies. |
| `setup.py` and `setup.cfg` | Tell ROS how to build and install the package. |
| `resource/bulldozer` | Lets ROS find the package. |
| `bulldozer/__init__.py` | Marks the Python package; future control code goes here. |

These files all have equivalents in his project. The root `CMakeLists.txt`,
`src/`, `static/`, and `worlds/` also follow his layout. The CMake and C++
files are future physics-plugin placeholders; they are not needed to launch
this ROS movement base.

## Build and run when ready

From the repository root, enter the robot package, as in his instructions:

```bash
cd bulldozer
source /opt/ros/jazzy/setup.bash
colcon --log-base /dev/null build --symlink-install
source install/setup.bash
ros2 launch bulldozer robot.launch.py
```

Building automatically creates `build/` and `install/` inside `bulldozer/`.
`build/` holds temporary build files. `install/` holds the generated package
files ROS uses to launch it. The many files inside are generated by the
build tools; you do not write or maintain them. His project creates these
too when built. The command above disables colcon's saved build logs.

The project is currently left as source files only. Build it before launching.
